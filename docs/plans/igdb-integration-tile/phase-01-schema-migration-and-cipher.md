# IGDB integration tile — Phase 1: Schema migration + cipher

## Goal
Add the `integration_credentials` table (Drizzle migration 0018) and an
`IntegrationCipher` port with an AES-256-GCM implementation. The cipher
encrypts a secret string at rest using a key derived from `BETTER_AUTH_SECRET`.
This phase touches infrastructure only — no domain logic yet.

## Design decisions
- Single table, columns: `id` (text PK, UUID), `user_id` (text, FK to `user.id`),
  `integration` (text, e.g. `'igdb'`), `enabled` (integer 0/1, default 0),
  `client_id` (text, plaintext — Client ID is NOT a secret),
  `client_secret_ciphertext` (text, base64 of `iv ‖ ciphertext ‖ authTag`),
  `last_verified_at` (integer, unix ms, nullable),
  `created_at` (integer, unix ms),
  `updated_at` (integer, unix ms).
- Unique index on `(user_id, integration)` — one row per user per integration.
- Cipher is AES-256-GCM via Node's `crypto` module (available under Bun).
- Encryption key is derived once per process from `env.BETTER_AUTH_SECRET`
  with HKDF-SHA256: `salt = SHA-256('apex.integration-cipher')`, `info = 'apex.integration-cipher.v1'`.
  Output length 32 bytes (AES-256).
- IV is 12 random bytes per encryption (GCM standard). Auth tag is 16 bytes.
- Storage layout: base64 of `iv (12) ‖ ciphertext ‖ authTag (16)`.
- Cipher is exposed as a port (`IntegrationCipher`) in `domain/integrations/integration-cipher.ts`
  so use-cases in later phases can depend on the interface, not the implementation.
- Failure modes are explicit: `tampered` (auth tag mismatch), `malformed`
  (wrong base64 / too short).

## Constraints
- TDD: write the cipher test FIRST (RED), then the implementation (GREEN).
- The cipher port is framework-free TypeScript — no Drizzle, no Hono, no Zod imports.
- Use `crypto.hkdfSync('sha256', ...)` and `crypto.createCipheriv('aes-256-gcm', ...)`.
- The derived key MUST be cached at module scope (computed lazily on first call).
  Re-derivation per encrypt is wasteful and a hot-path footgun in later phases.
- Cipher returns `Result<string, CipherError>` for decrypt; encrypt returns plain string.
- DO NOT log the plaintext or the ciphertext anywhere.
- DO NOT pass the raw `BETTER_AUTH_SECRET` to the cipher constructor — derive
  the key inside the implementation, behind a `getKey()` private function.
- Follow Biome formatting: 2 spaces, single quotes, semicolons, trailing commas.

### Step 2: AES-256-GCM cipher implementation (GREEN)
**File:** `apps/api/src/infrastructure/integrations/aes-256-gcm-cipher.ts`

Implement the `IntegrationCipher` interface. Use `crypto` from Node:
- `hkdfSync('sha256', Buffer.from(env.BETTER_AUTH_SECRET, 'utf8'), salt, info, 32)`
  where `salt = createHash('sha256').update('apex.integration-cipher').digest()`
  and `info = Buffer.from('apex.integration-cipher.v1', 'utf8')`.
- Cache the derived key in a `let key: Buffer | null = null` at module scope.
- `encrypt(plaintext)`: 12-byte random IV → AES-256-GCM → return base64 of
  `Buffer.concat([iv, ciphertext, authTag])`.
- `decrypt(ciphertext)`: decode base64 → split into iv/ct/tag → set auth tag
  → catch any decipher error and return `err({ kind: 'tampered' })`. If the
  input cannot even be split (too short, bad base64), return `err({ kind: 'malformed' })`.

Export the class as `Aes256GcmCipher` (named export, no `default`).

Run the tests → GREEN.

**Result:** cipher tests pass.

**What to write in `schema.ts`:**

```ts
export const integrationCredentials = sqliteTable(
  'integration_credentials',
  {
    id: text('id').primaryKey(),
    userId: text('user_id')
      .notNull()
      .references(() => user.id, { onDelete: 'cascade' }),
    integration: text('integration').notNull(), // 'igdb' for now
    enabled: integer('enabled', { mode: 'boolean' }).notNull().default(false),
    clientId: text('client_id').notNull(),
    clientSecretCiphertext: text('client_secret_ciphertext').notNull(),
    lastVerifiedAt: integer('last_verified_at', { mode: 'timestamp_ms' }),
    createdAt: integer('created_at', { mode: 'timestamp_ms' }).notNull(),
    updatedAt: integer('updated_at', { mode: 'timestamp_ms' }).notNull(),
  },
  (t) => ({
    userIntegrationUnique: uniqueIndex('integration_credentials_user_integration_unique').on(
      t.userId,
      t.integration,
    ),
  }),
);
```
Match the existing import / naming style (look at `idempotencyKeys` in the
