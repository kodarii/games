### V3-F2 (platform pin in Test 1) — **OPEN — B-3 regression re-introduced for platforms**

**Plan line 609** seeds platforms via:
```

```

Schema at `apps/api/src/infrastructure/db/schema.ts:59`:
```

```

**`platforms.id` is INTEGER autoIncrement, not text.** The Test 1 seed uses a string literal `'p-pc'`. This is the exact same defect class as B-3 from V1/V2 (string id seed on integer-PK table), now reintroduced for the platforms table. Even if Bun's `bun:sqlite` may coerce silently due to SQLite's type affinity (TEXT can be stored in INTEGER column with loose typing), this is not robust and will likely fail with a typecheck error against `NewPlatformRow` (`$inferInsert` produces `id?: number | undefined`).

**Recommendation:** rewrite the seed in 05-08 Task 3 Step 5 (line 609) to omit `id` entirely (autoincrement) and remove `updatedAt`:
```

  { userId: TEST_USER_A, name: 'PC', externalId: 'p-pc-ext', createdAt: new Date() },
  { userId: TEST_USER_A, name: 'PS5', externalId: 'p-ps5-ext', createdAt: new Date() },
```

### F-07-1 ordering (Step 0 STOP gate) — **FIXED in plan; minor weakness in mechanism**

Verified at `05-07-PLAN.md:116-126`: Step 0 in Task 1 `<action>` lists the four `bun test` files + three architectural greps, with the literal sentence: "If ANY of these fail, STOP. Do not write any CONCERNS.md marker." ✓

**Minor weakness (sub-issue):** the STOP instruction is prose-only. A planning agent reads "STOP" semantically and is expected to halt. There is no `set -e`, no `&&` chain, no exit code check in the literal bash block. The four `bun test` invocations are chained on one shell line (`bun test file1 file2 file3 file4`) which DOES fail-fast at the first failing file because bun:test treats the whole invocation as one process — the exit code from that single invocation is non-zero if any of the four files fail. The three subsequent `test "$(...)"` greps will then run regardless (unless the agent honors the STOP). Recommendation: rewrap Step 0 as a `&&`-chained block so a shell-level non-zero short-circuits the whole gate:
```bash
bun test ... && \
test "$(grep ...)" -ge 2 && \
test "$(grep ...)" -eq 0 && \
rg ...
```
Non-blocking; the prose instruction is sufficient for an LLM executor, but a `&&` chain hardens it.
