<objective>
Zapinać Hono route ordering regression testem w `apps/api/src/routes/games.test.ts`. ROADMAP SC-5 wymaga testu w tym pliku weryfikującego route precedence dla `/api/games/metadata/*` vs `/:externalId`.

Purpose: Hono route matching jest **registration-order sensitive**. Jeśli przyszły contributor zarejestruje `/:externalId` PRZED `/metadata/*`, wtedy `/api/games/metadata/...` zostanie dopasowane do `:externalId === 'metadata'` → handler dla single-game-lookup zwróci coś (400/404/200) zamiast routować do metadata sub-routera. Sama asercja `not.toBe(404)` jest za słaba.

**Q9 (Endpoint deterministyczny):** Pre-Q9 wariant pinował na `GET /metadata/candidates` z body-shape `body.type === '/errors/feature-disabled'` gdy status=503. Grilling ujawnił defect: ten body-shape pin jest deterministic TYLKO w środowisku BEZ creds IGDB (CI bez seeded creds → null chain → 503). Z seeded creds dev-env: status=200/400/502, body nieprzewidywalny, ifowy guard `if (res.status === 503)` nie wystrzeli — pozostaje tylko `not.toBe(404)`, dokładnie ta "za słaba" asercja którą plan sam dyskwalifikuje. Narracja "konstrukcyjny RED" była fałszywa: pin łapał regresję statystycznie (przez CI null-chain), nie konstrukcyjnie.

**Q9 superseding decision:** Pin endpoint przeniesiony na `GET /api/games/metadata/status` — endpoint zwraca **ZAWSZE 200** z `{igdbConfigured: boolean}` (apps/api/src/routes/games-metadata.ts:13 — `r.get('/status', c => c.json({igdbConfigured: deps.chainHolder.isConfigured()}, 200))` — żaden chain check, żaden gate). Body-shape pin: `expect(body).toHaveProperty('igdbConfigured')` + `expect(typeof body.igdbConfigured).toBe('boolean')`. Dyskryminator `igdbConfigured: boolean` jest emitowany WYŁĄCZNIE przez games-metadata sub-router. `:externalId` handler zwraca game-shape body (`id, title, developer, ...`) bez tego pola. Body-shape pin failuje konstrukcyjnie przy swap-regression — **deterministic regardless of env** (creds seeded vs null).

Output: Nowy `describe('route ordering pin')` w istniejącym `games.test.ts`; DWA `it(...)`:
  - Test 1 (Q9): body-shape pin dla `GET /api/games/metadata/status` — status === 200 + `body.igdbConfigured` typeof boolean
  - Test 2: counter-weight — `/api/games/:externalId` dla non-reserved slug nadal trafia w :externalId handler

**Type: regression-pin.** RED jest dowiedziony **konstrukcyjnie** i **env-independently** przez Q9 body-shape pin (`igdbConfigured: boolean` to deterministic dyskryminator). Manual swap jest opcjonalny dla lokalnego debugowania, ale NIE jest acceptance criterion. Pre-Q9 fallback na `feature-disabled` body discriminator jest UNAVAILABLE w Q9 — nie polegamy na statusie chain'a.
