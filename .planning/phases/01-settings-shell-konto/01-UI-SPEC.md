## Spacing Scale

Project uses Tailwind defaults (4px base unit, no custom `spacing` extension in `tailwind.config.js`). Phase 1 conforms to the 8-point scale:

| Token | Tailwind class | Value | Usage in Phase 1 |
|-------|----------------|-------|-------------------|
| xs | `gap-1`, `p-1` | 4px | Icon gap inside nav-link (`<Svg size={14}/>` to label) |
| sm | `gap-2`, `p-2`, `space-y-2` | 8px | Field gaps inside form rows; checkbox + label |
| md | `gap-4`, `p-4`, `space-y-4` | 16px | Form field stack inside cards; nav-link vertical rhythm |
| lg | `p-6`, `space-y-6` | 24px | Card inner padding (Specifics: "card style padding ~24px"); gap between cards on Account page |
| xl | `gap-8`, `py-8`, `space-y-8` | 32px | Page heading → first card gap; settings layout left/right gutter |
| 2xl | `py-12` | 48px | Reserved (not used in Phase 1) |
| 3xl | `py-16` | 64px | Reserved (not used in Phase 1) |

**Container width for Account page** (D-19): `max-w-[720px]` (form-heavy settings convention, Linear-style). Page-level container: full-bleed inside `AppLayout`'s `<Outlet />`.

**Side-nav width:** fixed `w-[220px]` (matches existing app sidebar density rhythm; Linear `/settings` secondary-sidebar reference).

**Exceptions:**
- Nav-link inner height `py-[10px]` (10px) — inherited from existing `NavRow` pattern in `sidebar.tsx:52` for visual rhythm consistency (FE-07 requires match).
- Section-label tracking `pb-[6px] pt-4` — inherited from `SectionLabel` in `sidebar.tsx:95`.
- Card titles use `text-[14px]` (14px) per Specifics; sits between Tailwind `text-sm` (14) and `text-base` (16).

**Accent reserved exclusively for** (no other elements):
1. Active side-nav link in `settings-nav.tsx` (text + leading icon)
2. Primary submit button "Zapisz" in `account-password-form.tsx`
3. Default focus ring on form inputs (Tailwind `ring` token already targets `apex-accent` via existing design system — do not override)

**Destructive reserved exclusively for:**
1. "Wyloguj wszystkie sesje" trigger button (`<Button variant="destructive">`)
2. Confirm action inside the AlertDialog ("Wyloguj wszystkie")

**Anti-rules:**
- Disabled nav items (Integracje, Dane, Wygląd in Phase 1) MUST use `text-apex-disabled` or `text-apex-muted` + `cursor-not-allowed`. No accent, no destructive.
- "Anuluj" button in AlertDialog uses default/outline variant — never accent, never destructive.
- Success toast (sonner `richColors`) renders green automatically — no custom color override.

### Empty states

Phase 1 has **no empty states**: the page renders 3 cards that are always populated (email always exists for an authenticated user; password form is always interactive; revoke-sessions card is always interactive).

If `useSession()` returns `data === undefined` for any reason → the entire page is gated by `ProtectedRoute` upstream, which redirects to `/login`. No skeleton needed inside settings.

## Interaction Contracts

### Side-nav active-state contract
- Active link: `bg-[oklch(95%_0.02_220)] font-semibold text-apex-accent` + icon at `text-apex-accent` (mirrors `sidebar.tsx:54`).
- Inactive link: `text-apex-ink-3 hover:bg-apex-surface-hover hover:text-apex-ink` + icon at `opacity-55`.
- Disabled item: `<span aria-disabled="true">` with `text-apex-disabled cursor-not-allowed`, wrapped in shadcn `Tooltip` showing `Wkrótce`. **Not** an anchor/NavLink — non-interactive.
- Match detection: `pathname.startsWith('/settings/account')` (loose match, mirrors `sidebar.tsx:39`).

### Password form contract
- Pattern: uncontrolled inputs + `FormData` (MEMORY: `feedback_react_autofill_uncontrolled`); see `login.tsx:14-36` as canonical.
- Local state: `error: string | null`, `isPending: boolean`. No per-field controlled state.
- Submit handler: `e.preventDefault()` → `new FormData(form)` → client-side mismatch check → `authClient.changePassword({ currentPassword, newPassword, revokeOtherSessions: <checkbox> })`.
- Success: `toast.success('Hasło zmienione')` + `form.reset()`. **No** `refetchSession()`, **no** navigate.
- Failure: map `error.code` via inline switch → set `error` state → render inline red banner above form (same DOM structure as `login.tsx:43-47`).

### Revoke-sessions contract
- Trigger button (destructive variant) opens shadcn `AlertDialog`.
- AlertDialog action (destructive variant) handler — strict order:
  1. `await authClient.revokeSessions()`
  2. `await refetchSession()` ← **required by MEMORY** `feedback_better_auth_session_refetch`
  3. `qc.removeQueries({ queryKey: ['games'] })` (mirrors `sidebar.tsx:116`)
  4. `navigate('/login', { replace: true })`
- AlertDialog cancel: closes dialog, no side effects.
- Disable trigger button while mutation in flight (local `isPending` state).

### Focus management
- Page load on `/settings/account`: native browser focus on first heading (no programmatic focus stealing).
- AlertDialog open: focus traps inside dialog (Radix default), restores to trigger on close.
- Form submit: errors render above form; do not auto-scroll, do not auto-focus error field (single-screen form).

### Keyboard
- All shadcn primitives provide Radix-grade keyboard support out of the box (no hand-rolled handlers needed).
- Side-nav: `Tab` walks active NavLinks; disabled `<span>` items are skipped (no `tabIndex`).

## Responsive

Project is desktop-first per PRODUCT.md ("biurko, monitor, pełen skupienia"). Mobile is **out of scope** for v1 (Out of Scope table, REQUIREMENTS.md:86).

Settings shell behavior at smaller widths (graceful, not optimized):
- ≥1024px (lg): side-nav fixed `w-[220px]` + content fills remainder up to `max-w-[720px]`.
- 768–1023px (md): same layout; content shrinks naturally.
- <768px (sm): **not optimized**. Side-nav stays visible but content may overflow. This is acceptable for Phase 1 — no PWA, no mobile-first work in this milestone.

`AppLayout` already handles top-level sidebar collapse (`SidebarProvider` + `Sheet`) — settings nav does NOT replicate that mechanism (D-05). It is a static secondary nav.

## Brand / Voice

Per CLAUDE.md "Brand" + PRODUCT.md + Specifics:
- **Linear / Raycast feel** — precyzja, gęstość z oddechem, dane mówią same za siebie.
- **No dark-gamer aesthetic, no gamification.** Neutral palette only.
- **Polish microcopy** — short, direct, no exclamation marks, no emoji.
- Toast confirmations are 2 words ("Hasło zmienione") — no celebratory padding.
- Destructive copy is informative, not alarmist ("Zostaniesz przekierowany…", not "UWAGA!").
