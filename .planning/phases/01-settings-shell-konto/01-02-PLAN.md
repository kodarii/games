## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → better-auth `/change-password` | Authenticated mutation; old password verified server-side; better-auth applies built-in rate-limit (`auth.ts:23-31`, window=60s, max=100) |
| FormData → React state | Untrusted input crosses here on submit; React escapes by default; no `dangerouslySetInnerHTML` introduced |
| Error code → UI string | Server-supplied `error.code` is rendered through hard-coded Polish copy map, never interpolated raw |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | Calling `changePassword` without an authenticated session | mitigate | `/settings/*` is gated by `<ProtectedRoute />` (`main.tsx:30`); better-auth's `changePassword` server endpoint additionally requires a valid session cookie. Double-gate (route + server) holds. |
| T-02-02 | Tampering | Bypassing the client-side `newPassword === confirmPassword` gate via crafted POST | accept | The mismatch check is a UX nicety only — better-auth does not have a `confirmPassword` concept.
