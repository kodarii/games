<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → better-auth `/revoke-sessions` | Authenticated, destructive mutation; revokes ALL sessions for the current user |
| AlertDialog → onConfirm | UX gate; user explicitly confirms before destructive call |
| Post-revoke → route guard | After `refetchSession`, `useSession` returns `null`; `ProtectedRoute` would redirect — we beat it to the punch with explicit `navigate('/login')` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | Calling `revokeSessions` without authn | mitigate | `/settings/*` gated by `<ProtectedRoute />`; better-auth's server-side `revokeSessions` endpoint additionally requires a valid session. Double-gate holds. |
| T-03-02 | Tampering | Bypassing the AlertDialog (programmatic click on the underlying call) | accept | The AlertDialog is a UX gate against accidental click, not a security boundary. A determined client could call `authClient.revokeSessions()` from the console — but it's their own session and the same browser. Acceptable. |
| T-03-03 | Information disclosure | AlertDialog leaks the destructive intent before confirmation | mitigate (by design) | Polish copy `Zostaniesz przekierowany na ekran logowania. Twoja kolekcja pozostanie nietknięta.` explicitly tells the user what will happen — that IS the mitigation against accidental clicks. |
| T-03-04 | Denial of service | User rapidly clicks the trigger button | mitigate | `disabled={isPending}` on the trigger prevents repeat opens during in-flight mutation. Better-auth's built-in rate-limit (`auth.ts:23-31`) applies to repeated revoke calls. |
| T-03-05 | Repudiation | Successful revoke without audit trail | accept | Single-user app; better-auth server logs the revoke action with userId. Acceptable for v1. |
| T-03-06 | XSS | AlertDialog renders user-supplied copy | n/a | All copy is hard-coded Polish strings; no user input rendered in the dialog. |
| T-03-07 | Elevation of privilege | A revoked session continues to work for cached requests | mitigate | `qc.removeQueries({ queryKey: ['games'] })` drops user-scoped cache; `navigate('/login', { replace: true })` forces a full route remount under `ProtectedRoute` which now sees `data === null` (post-refetchSession) and would re-redirect to `/login` anyway. The explicit navigate is the belt; ProtectedRoute is the braces. |
| T-03-08 | Spoofing | Unauthenticated access to `/settings/account` | mitigate | Source contract pinned by Task 3's `protected-route.test.tsx` regression test.
