<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React render → ErrorBoundary | Synchronizny error w renderze deszczu komponentów; klasowa boundary łapie go w `getDerivedStateFromError` |
| ErrorBoundary → DOM (fallback) | Statyczny copy renderowany do DOM; brak user input echoed back |
| componentDidCatch → console | Strukturalny log; w v2 hook do Sentry/Axiom (SEC-V2-01) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information disclosure | Fallback UI echoes `error.message` / `componentStack` to user | mitigate | Fallback renderuje WYŁĄCZNIE statyczny polski copy (`Coś poszło nie tak.` + opis). `error.message` i `componentStack` lądują tylko w `console.error` (DevTools, lokalnie). Pin w `<action>` Task 1: "NIE renderuj error.message ani componentStack". |
| T-04-02 | Tampering / XSS | Inline HTML w fallback'u | n/a | Cały copy jest hard-coded string literals; brak `dangerouslySetInnerHTML`, brak `innerHTML`, brak user-supplied content w fallback. Pin: source musi mieć tylko statyczny copy. |
| T-04-03 | Denial of service | Loop: render error → fallback → reload → render error → ... | accept | `window.location.reload()` jest user-triggered (klik przycisku), nie automatyczny. Jeśli deterministic crash pojawia się przy boot — user widzi statyczny fallback i może zamknąć tab. Soft auto-reset (per RESEARCH §Pattern 1 line 208) odrzucony — full reload jest semantycznie najbezpieczniejszy. |
| T-04-04 | Information disclosure | Strukturalny log w `console.error` wycieka stack frames z user-PII jeśli error.message zawiera dane | accept | Single-user app na VPS — DevTools dostępne tylko właścicielowi. W v2 (SEC-V2-01 Sentry) trzeba będzie scrubbować PII przed wysłaniem. Format `{event,error,componentStack}` jest gotowy do wpięcia scrubber w v2. |
| T-04-05 | Repudiation | Brak audit trail erroru poza local console | accept | Single-user; przyjęte. SEC-V2-01 to closes (Sentry/Axiom). |
| T-04-06 | Elevation of privilege | Sesja/cookies/route guards bypass przez fallback | n/a | Fallback renderuje POZA `RouterProvider` (zastępuje go); żadne dane chronione nie są w fallback'u. `QueryClientProvider` (rodzic) cache'a jest niezmieniony, ale fallback go nie czyta. Po `window.location.reload()` `ProtectedRoute` znów montuje się normalnie. |

ASVS L1 mapping: V14 (Configuration) — error handling configured to fail closed (no info disclosure). V11 (Business logic) — n/a, this is render-time error trap, not business logic.
